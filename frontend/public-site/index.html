Measure AI's Resource Footprint From Your Developer Workflow

AI Footprint is a provider-neutral platform that estimates the physical resource impact — energy, water, carbon — of AI workloads: conversational, image, video, audio, coding/agentic, RAG and embeddings. Every estimate is a range with confidence, evidence level and methodology version — never a fabricated exact number.

What AI Footprint does

AI usage spans conversational AI, image generation, video generation, audio, coding assistants, code review, AI agents, RAG and embeddings. Users generally see the output of AI but not the infrastructure and resource implications behind producing it. AI Footprint exposes estimated water consumption, energy consumption, carbon emissions and compute/resource intensity for a workload, built around an AIWorkload abstraction: an organization contains projects, which contain applications, which submit AI workloads that produce estimates.

Why developers need AI resource intelligence

The resource cost of an AI call is invisible from the API response alone. As AI usage scales inside a product, that invisible cost scales with it. AI Footprint gives developers and organizations a way to measure it directly from the same workflow they already use to call AI providers — without requiring them to understand data-center infrastructure, and without pretending to know more than the available evidence supports.

CLI

A thin command-line client — event, estimate, usage, compare, benchmarks — built on the Python SDK, with no estimation logic of its own. No TTY, no browser, no interactive confirmation required, which makes it safe to run in CI/CD. 

# once published (see the SDK note below for current status)
pip install aifootprint-cli

export AIFOOTPRINT_API_KEY="afp_live_..."
export AIFOOTPRINT_BASE_URL="https://your-ai-footprint-instance.example.com"

aifootprint estimate \
  --provider openai --model model-id \
  --modality text --activity-type text_generation \
  --input-tokens 2000 --output-tokens 1000

Python SDK

A thin, typed REST client (httpx + pydantic, sync-only) — it sends requests and parses responses, and never estimates, aggregates or ranks anything the backend hasn't already computed. 

# once published (both packages are currently pre-release —
# see the repository's docs/RELEASING.md for exact status)
pip install aifootprint
from aifootprint import AIClient

client = AIClient()  # reads AIFOOTPRINT_API_KEY / AIFOOTPRINT_BASE_URL

estimate = client.estimates.create(
    provider="openai", model="model-id",
    modality="text", activity_type="text_generation",
    input_tokens=2000, output_tokens=1000,
)
print(estimate.energy.min, estimate.energy.max, estimate.confidence)

CLI → SDK → API

There is exactly one HTTP/authentication boundary in this stack. The CLI calls the SDK; the SDK calls the REST API. Neither the CLI nor the SDK duplicates estimation or authentication logic — the backend is always the source of truth for methodology and calculation.

Ranges, confidence and provenance

AI Footprint does not claim to measure the exact physical resource consumption of an individual request unless authoritative measurement data is available. Every estimate is presented as a range, with an explicit confidence level, evidence level, methodology version, stated assumptions and source provenance — never averaged into a single number, and never rounded up to imply completeness when data is partial.

AI Footprint does not rank, score, or declare a "winner," "greenest," or "best/worst" provider or model, and does not make unsupported environmental claims. Comparisons (compare, benchmarks) return each candidate's independent result in the order requested — nothing more.

Privacy-first by design

The CLI and SDK operate entirely on workload metadata. They never require, and never automatically collect, prompt text, model response text, source code, private files, browser data, cookies, or third-party provider credentials. An API key is sent only as an Authorization: Bearer header — never logged, never printed, never placed in a URL.

Roadmap

Available today: the CLI, the Python SDK and the REST API.

Planned, not yet implemented: direct AI-provider integrations (e.g. OpenAI, Anthropic, cloud AI services), OpenTelemetry GenAI telemetry ingestion, cloud-platform integrations, application integrations, a Browser Extension, and mobile (iOS/Android) observation. These are architected around the same AIWorkload model the CLI and SDK already use, so they will feed the same estimation engine and the same range/confidence/provenance semantics described above — they are not available yet, and this site will not claim otherwise.

AI Footprint is a provider-neutral platform for estimating the resource impact of AI workloads. Estimates are ranges with confidence and provenance, not guarantees of exact physical consumption.
